# 送信テストの手順（social-design-center@eikei.ac.jp）

確かめたいことは2つ。

1. このアドレスから送ったメールが、学外の受信箱（迷惑メールフォルダーではなく）に届くか
2. システム（プログラム）からこのアドレスを使って送れるか

A と B は情報システム部門の承認なしで、今日試せる。C は承認後に行う。

## A. 手動で送って、届き方と認証を確かめる（10分）

1. Outlook で social-design-center@eikei.ac.jp を差出人にして、次の宛先にテストメールを送る。
   - 自分の Gmail アドレス
   - 可能なら Yahoo!メール、携帯キャリアのアドレスも
2. 各受信箱で、**受信トレイに届いたか**、迷惑メールフォルダーに入っていないかを見る。
3. Gmail で届いたメールを開き、右上の「︙」→「メッセージのソースを表示」を選ぶ。上部の表で次の3つを確認する。

| 項目 | 期待する結果 |
|---|---|
| SPF | PASS |
| DKIM | PASS（ドメインが eikei.ac.jp か、大学の M365 のドメイン） |
| DMARC | PASS |

3つとも PASS なら、このアドレスは学外へきちんと認証付きで送れている。どれかが FAIL や表示なしなら、結果の画面を保存して共有してほしい（情シスへの相談事項になる）。

## B. Power Automate からこのアドレスで送る（20分）

システムから送る経路の代わりとして、Microsoft 公式の自動化ツールで「プログラムからこのアドレスで送れるか」を試す。

1. https://make.powerautomate.com を大学の M365 アカウントで開く。
2. 「作成」→「インスタント クラウド フロー」→ トリガー「フローを手動でトリガーする」を選ぶ。
3. アクションを追加：「Office 365 Outlook」→「**共有メールボックスからメールを送信する (V2)**」。
   - 元のメールボックス アドレス：social-design-center@eikei.ac.jp
   - 宛先：自分の Gmail アドレス
   - 件名・本文：「送信テスト」など
4. 保存して「テスト」→「手動」で実行する。

| 結果 | わかること |
|---|---|
| 成功し、Gmail に届いた | このアドレスはプログラムから送れる。自分にこのアドレスの「代理送信（Send As）」権限がある |
| 権限のエラー（Send As がない、など） | アドレス自体は使えるが、自分に代理送信の権限がない。情シスに権限付与を頼む |
| Power Automate が使えない・開けない | 大学で Power Automate が制限されている。システム側の送信（C）で進める |
| 「共有メールボックスではない」系のエラー | このアドレスは共有メールボックスではない（グループや配布リストの可能性）。種類を情シスに確認する |

B の結果は、アドレスの種類の確認（開発ボードの確認事項）の答えにもなる。

## C. このシステムから送る（情シスのアプリ登録後）

1. 情シスから次の3つを受け取り、`.env` に書く（パスワードと同じ扱い。チャットやメールに貼らない）。

```
MAILER=graph
GRAPH_TENANT_ID=（ディレクトリ ID）
GRAPH_CLIENT_ID=（アプリケーション ID）
GRAPH_CLIENT_SECRET=（クライアント シークレット）
```

2. 管理画面で配信を作り、「テスト送信」で自分の Gmail に送る。A と同じく受信トレイと認証結果を確認する。
3. 職員3〜5人だけの配信先リストを作り、実際に予約して送る。全員に届くこと、配信停止リンクが動くことを確認する。
